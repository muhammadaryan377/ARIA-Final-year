## Weekly Sprint Workflow

1. **Sprint planning:** Divide tasks among team members and agree on a **one-week deadline**. Define acceptance criteria and the intended branch.
2. **Independent development:** Each member implements their assigned work on their own existing development branch.
3. **Code submission:** Members push their changes. The team reviews relevant work, tests and any merge conflicts.
4. **Integration:** After the last relevant teammate has pushed and the changes are approved, merge into the agreed integration branch.
5. **Sprint review:** Record what passed, what was integrated, what remains open and what needs improvement.

### Workflow Status Definitions

- **To Do:** Task is listed but acceptance work has not started.
- **In Progress:** Active work is underway on an assigned branch.
- **Review / Testing:** Code or evidence is available and requires verification before acceptance.
- **Done:** Acceptance criteria passed, integration approved, and evidence links recorded.

### Definition of Done

- [ ] Code or documentation change has a linked commit or PR.
- [ ] Required validation has actually been performed and its results recorded.
- [ ] Integration effects and any regressions have been reviewed.
- [ ] Relevant branch changes have been merged to the approved target.
- [ ] Issue includes supporting evidence and a short completion note.
